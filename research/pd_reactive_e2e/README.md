当前只验证每个 D 实例一个在线请求；4 个客户端完整任务（两个暖任务、两个新任务）及其依赖、工具等待和到达时刻保留，等待进入实例的时间计入端到端延迟。r6–r9 的多请求空阶段控制环发生阻塞，CPU 顺序检查未能覆盖跨 rank 的执行进度，两个候选顺序调整均已撤回。此轮只检查有界流程及成本，不能解释为多请求吞吐、KV 容量弹性或高并发性能验证。

先跑一对有限流量，完整收尾。报告请求与任务端到端延迟、TTFT、TPOT、原有 SLO 达标率及失败／未完成。GPU 时间区分整节点预约、实际常驻 worker（含待命／加载）与逻辑权重布局。原地路径保留小的第三 rank；实例对照在触发后从已就绪的 CPU 权重银行启动，启动时间计入结果，因此首轮不能把全部差异归因于卡数粒度。
