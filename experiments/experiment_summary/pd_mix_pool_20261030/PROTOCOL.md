# 35B：Prefill／Decode 混合负载能否支持 EP／PP 配比

两台已预约的四卡 H100 节点独立复测。每个候选部署只使用同一节点四张卡；跨节点不汇总均值。

候选为 EP4、2×EP2、4×单卡、2×PP2、EP2＋PP2。EP 的 Attention 为对应 DP，TP1。完整 Qwen3.6-35B-A3B，BF16 权重与 KV、FP32 GDN。所有实例使用真实模型、同一源码与 Expert 后端。

先测冷 Prefill：P=0；B32/Q512、B16/Q8192、B8/Q16384；O=1。随后测真实到达：64 个请求、16/32 请求每秒；长输入短输出请求 Q8192/O16，占25%、50%、75%；其余为短输入长输出 Q256/O256。请求首 token 唯一且每轮清空缓存。请求的 P 和 D 始终在同一实例完成。

每点单独预热、三轮完整无 profiler 计时，保留全部样本。报告平均 TTFT、TPOT、E2E，以及完整流量完成时间、P/D 类别指标、实际客户端到达偏差。P95 为补充，不能用最快或最慢轮代替均值。SLO 敏感性预先列为 TTFT 200/500/1000/2000 ms、TPOT 10/15/20/30 ms。

同质副本按当前未完成请求数分配；DP rank 同样按未完成请求数分配。混合池额外测试 P 类到 PP、D 类到 EP，以及反向分配。类别来自预先固定的输入/输出请求规格，不能用未到达请求的信息。路由决策、目标、实际到达/完成均保存。整请求粘性，无 KV/GDN 迁移。

现有最快 policy9 需要固定的消息尺寸和稳定的 Decode 槽位，不能直接接受任意 Prefill/变批。此次 PP 使用同一最新版代码中可变尺寸的原生消息路径和提前发送 policy1；先与原生 policy0 对比完整输出，失败就显式退回 policy0，并保留失败资格记录。固定批次 lookahead 的历史结果不冒充此次混合流量结果。动态优化未来仍有空间，负结论限于实际资格通过的实现。

每完整模型 GPU 等价分配80个 GDN slots、147456个 KV token 上限；PP 按层数换算，静态显存比例0.95。实际容量和并发从原生日志读取。Prefill 每 Attention 实例4096 token chunk；PP 流量微批上限8，冷 Prefill 按 B/4。大消息走 DeepEP Normal，Decode 走 LL，保存实际 dispatch 类型计数。

验收：请求数、输入/输出长度、冷缓存命中0、四个 rank 完整模型加载、真实 Prefill/Decode forward、PP 资格记录、完整轮次、原始到达偏差、Guard 缓存和拥有进程清理均可追溯。不能把 CPU 缓存恢复历史结果混入本轮冷请求比较。

本轮先验证动态配比的机会，不把静态最优布局随流量变化称为在线扩缩容收益。如果 PP 进入最优包络且混合池有净收益，再测在线选择与重配置成本；如果没有，只能得出上述范围未支持，不外推为所有模型、缓存和实现均无机会。
