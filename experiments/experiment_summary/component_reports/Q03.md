# Q03：H100 双卡 EP2 与两槽 PP2，中等负载及接近容量上限

## 测的是什么

**请求数**指整批同时提交的独立请求；**已缓存上下文**指计时前已经由真实模型生成并驻留 GPU 的前缀，不是本轮重新 Prefill 的输入。Prefill 测新增输入、输出 1 token；Decode 每条新增 1 token、生成 128 token。本轮没有 CPU HiCache 换入、合成 KV 或 MTP；完整 CPU 权重 Bank 只用于加快模型加载。

**TTFT** 从发送请求到收到首 token；**TPOT** 是首 token 到最后 token 的时间除以后续 127 个输出；**端到端延迟** 到最后 token 为止；**吞吐**按整批完成时间计算，只计新输入或实际输出。形状预热、旧上下文准备和独立 profile 不计入正式计时。每格 3 轮；下表延迟均为请求均值，中位数和 P99 见完整报告。

模型 **Qwen3.5-122B-A10B-FP8，完整 48 层**。同一已预约 H100 节点 178、四张 80GB GPU：GPU0/1 跑 EP2，GPU2/3 跑 PP2，两对均为 NVLink NV6，同步并行测量，没有跨节点通信。EP2：每卡 Attention TP1、两个 Attention 数据并行副本，专家跨两卡 EP2；PP2：每卡 24 层，每层全部专家，每阶段 Attention TP1、Expert EP1。PP 始终两个等大槽位，8 请求拆为两组 4，16 请求拆为两组 8。

两组均使用 H100 原生 FP8 W8A8 DeepGEMM、BF16 KV、FP32 线性 Attention 状态，FA3 全 Attention、Triton 线性 Attention，实际 Decode CUDA Graph 已核验。EP2 Decode 使用低延迟 DeepEP 和原生 overlap；该引擎版本对 PP 自动关闭 overlap。

## PP 自身容量边界，单列，不作同工作量排名

实测逻辑 KV 容量：EP2 **237,952 token**，PP2 **750,848 token**，约 **3.16 倍**。PP 两个阶段存不同层，容量不能相加。

PP2 另测 16 请求、每条已缓存 **42,176 token**，总计 **674,816 token**，约占其自身容量 90%。新增 512、输出 1 的 Prefill 吞吐 **17151.85 token/s**；新增 1、输出 128 的 Decode 吞吐 **759.92 token/s**，平均 TPOT **19.498 毫秒**。

该工作量超过 EP2 的 GPU 全驻留容量；本轮没有替 EP2 运行 CPU HiCache／排队策略，因此只能证明 PP 能全驻留跑通，不能声称这个大工作量下 PP 比 EP 快多少。

## 优化和核验

- 通信缓冲区先初始化，再实测 KV；EP 的 Graph 和线性状态池按 DP 后的每卡 batch 配置。EP 全局状态池 88、每卡 44；PP 每阶段 84。
- 启用原生 `--mamba-max-states-per-path 1`，清掉沿途不再需要的中间 chunk 状态，保留末端、分叉和锁定状态。避免仅靠扩大状态池挤占 KV；没有改模型计算或状态精度。两组最长前缀驻留资格检查及全部正式请求缓存命中检查通过。
- PP Prefill 使用短 A/B/B/A 选出的发送就绪策略，本轮局部派生吞吐约 +1.08%，首 token 输出检查通过；Decode 保留原生产发送路径。7 项本轮协议测试与 7 项原生剪枝 CPU 测试通过。
- 仅计时外建缓存时每组最多 4 请求；正式计时中所有 8／16 请求仍同时提交，未按 GPU 容量客户端串行化。每轮缓存 Prefill 都从相同基础前缀开始，不把上一轮分支挤出缓存造成的重算混入结果。
- Guard 科学结果、完整 CPU 权重 Bank 使用、退出清理检查均通过，GPU 租约已释放。失败尝试原样保留，不混入正式表。

## 该怎样解释

**A100 上两槽 PP 的 Decode 吞吐优势，没有在本轮 H100 原生路径重现。** 三个同工作量 Decode 点里，PP 吞吐低约 20%–23%，尽管其首 token 更早。Prefill 不是固定胜负：8 条长缓存请求时 PP 吞吐高 19.69%；相同总缓存拆成 16 条请求时，本轮均值低 5.61%，但 PP 的平均 TTFT 仍较低。

独立 Decode Graph profile 中，中等负载的 EP 每卡完整 48 层 GPU 跨度约 9.93–10.04 毫秒；PP 两个 24 层阶段分别约 5.05／5.37 毫秒。EP Graph 中 DeepEP kernel 合计约 1.73–2.10 毫秒；PP Graph 中没有 DeepEP，但仍有 Graph 外的阶段传输与反馈。PP 每个阶段的 routed GEMM 合计约 1.84–2.09 毫秒，EP 完整层为 2.12–2.61 毫秒，显示 PP 集中专家并非没有计算代价。**这些是独立 profiler 样本，不能相加冒充请求 TPOT 或精确剩余归因。**

本轮不是“硬件型号”单变量实验：此前 A100 使用 W8A16 Marlin、关闭 Graph／overlap、Decode 走 normal 通信；H100 使用原生 W8A8、Graph，EP2 还启用了低延迟通信和 overlap。PP 在本引擎仍受 overlap 支持限制。本次验证了关键配置与短局部优化，未证明所有参数下的全局最优。每格仅 3 轮，PP 的 16 请求 Prefill 吞吐有波动，不能把小差异推广为普遍结论。
