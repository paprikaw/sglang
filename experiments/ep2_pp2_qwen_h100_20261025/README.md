# H100 双卡：EP2 与 PP2，中等负载与接近 KV 容量上限

## 配置和计时含义

模型是 **Qwen3.5-122B-A10B-FP8**，完整的 48 层，不是单层实验。两组各使用两张 H100 80GB：EP2 在两卡之间分配每层的专家，Attention 在两卡上各自处理一半请求；PP2 将前后各 24 层放在两卡，每层的专家不再跨卡划分。PP2 始终使用两个等大小的流水槽：8 条请求分成两组 4 条，16 条请求分成两组 8 条。

本轮使用 H100 原生 FP8 W8A8／DeepGEMM，BF16 KV Cache、FP32 线性 Attention 状态，FA3 全 Attention 与 Triton 线性 Attention；Decode CUDA Graph 已由实际启动日志和 GPU trace 核验。此前 A100 使用 W8A16 Marlin，因此跨代比较只能说明完整执行路径的趋势，不能把差异全部归因于 GPU 硬件。中等负载对齐此前的请求数、输入输出长度和缓存状态；本轮重新构造文本，不是历史请求逐 token 重放。

全部旧上下文均先由真实模型计算并保存在本次进程的 GPU 原生前缀缓存及线性 Attention 状态中。**不使用合成 KV，不在正式计时里重建上下文，也不测 CPU HiCache 换入。** CPU 权重 Bank 是独立的加载加速设施；不能将其称为 CPU KV Bank。没有开启 MTP。

TTFT 是每条请求从开始发送到收到首个输出 token 的时间；TPOT 是首 token 到最后 token 的时间除以后续 127 个输出 token；端到端延迟到收到最后一个输出 token 为止。吞吐按照整批请求实际开始至最后输出的时间计算。Prefill 吞吐只计本轮新输入，不把已经缓存的 token 再算一次。

## 三个共同负载点，加一个 PP 自身容量点

| 负载 | 请求数 | Prefill 开始前每条已缓存上下文 | 本轮 Prefill 新输入 | Decode 开始前每条已缓存上下文 | Decode 新输入／生成 |
|---|---:|---:|---:|---:|---:|
| 中等，与 A100 对齐请求数和长度 | 8 | 0 | 4096 | 4096 | 1／128 |
| 长上下文，接近 EP2 容量 | 8 | 26,752 | 512 | 26,752 | 1／128 |
| 同等总缓存、更细粒度请求 | 16 | 13,376 | 512 | 13,376 | 1／128 |
| 仅 PP2 自身容量边界，单列 | 16 | 42,176 | 512 | 42,176 | 1／128 |

共同负载使用两组实测逻辑容量中的较小值，保证同一行工作量一致。EP2 为 237,952 token，PP2 为 750,848 token。EP2 的两份 Attention 池可相加；PP2 两个阶段只存部分层，不能把它们报告的 token 容量相加。两个共同长上下文点的总缓存均为 214,016 token，约占 EP2 容量 90%，并为新输入、输出保留空间。

另测 PP2 自身约 90% 容量的 16 请求点，Prefill 每条新增 512、输出 1，Decode 每条新增 1、输出 128。该点的上下文比共同负载更长，单列展示，不能与 EP2 作同工作量的速度排名。最终预算中 EP2 全局线性状态池为 88（DP 后每卡 44），PP2 每阶段为 84；所有状态显存已从实际 KV 容量中扣除。两组均开启原生 `--mamba-max-states-per-path 1`，清理无用的中间 chunk 状态，保留末端、分叉和锁定状态；不改变模型计算或状态精度。

## 验证与本地调优

- 通过 Guard 使用单节点四卡的一份租约，两组运行在不重叠的 GPU 对上。CPU 权重 Bank 共用；记录实际 NVLink 拓扑和设备 UUID。
- 启动时核验两组实际 rank 的完整层数、FP8 权重类型与 H100 设备；通信缓冲区在 KV 容量计算前初始化。
- 对 PP 发送等待策略做已经预热的短 A/B/B/A，并检查对应输出。一旦输出检查失败或不足以确认，就不采用候选。Decode 不直接启用 A100 上尚未验收的候选。
- 每种形状先预热，再采三轮正式指标。每轮缓存 Prefill 前重建相同的基础前缀、使用未命中的新分支；中等负载则每轮清空前缀缓存。准备阶段每次最多 4 请求，避免占满线性状态工作空间；**正式计时的全部 8／16 请求仍同时放行**。Decode 必须报告旧前缀命中。
- Profile 在两组都完成该负载的正式计时后另采，避免一组的 trace 导出污染另一组的性能采样。
- 这是短局部调优及实测资格验证，不是所有后端、batch 和时钟条件下的全局最优证明。
