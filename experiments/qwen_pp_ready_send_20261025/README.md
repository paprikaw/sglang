# PP2 发送就绪优化

[完整结果与正确性边界](results/REPORT.md)。已加入总索引第 8 节 Q02；本目录保留实现、冻结输入和原始失败记录。

## 请求、配置和计时

- 完整 Qwen3.5-122B-A10B-FP8，069 的 GPU0/1，两张 A100 80GB、NV12 NVLink。Guard 按整节点 4 GPU 登记，无新预约。
- 两阶段 PP，每卡连续 24 层，Attention TP1、Expert EP1、两槽。Marlin W8A16、BF16 激活和 KV；CUDA Graph 与 overlap 关闭。
- Prefill：8 条请求，每条没有旧缓存，新增输入 4096 token，生成 1 token。计时从请求放行至输出，包含发送就绪等待；不计加载、预热和 profiler。
- Decode 回归：8 条请求，每条先独立准备 4096 个真实 GPU 缓存 token，再新增输入 1 token、生成 128 token；前缀构建不计时，没有 CPU HiCache 换入。
- 原版和候选在同一个已加载模型内交替；TTFT 是放行到首输出，单输出 Prefill 的端到端延迟等于 TTFT，TPOT 不适用。

## 改动

发送端原来可能在激活尚未算好时就发布 CPU 元数据，让接收端提前启动 NCCL kernel 等待。
候选先等待当前流的生产事件完成，再调用相同原生发送函数。张量、模型、路由和数学内核不变。
实现为实验私有 overlay，尚未默认改动共享引擎。

## 已验证的结果

`runs/two_slots_r3`：两种策略各预热两批，正式按原版→候选→候选→原版执行；每策略两批共 16 条正式 Prefill 请求。

| 指标 | 原版 | 候选 |
|---|---:|---:|
| 输入吞吐 token/s | 8160.97 | 9391.74 |
| 平均 TTFT 秒 | 2.3980 | 2.1383 |
| TTFT 中位数秒 | 2.3970 | 2.1397 |
| TTFT 样本 P99 秒 | 4.0295 | 3.4899 |

吞吐提高 15.08%，平均 TTFT 降低 10.83%；32 条正式请求的完整 token IDs 相同。
另采每策略一批 CPU/GPU trace，第一阶段投影从 6.3800→4.9118 毫秒/层，NCCL 等待与计算重叠显著减少。
5 项候选 CPU 单元测试通过；r3 Guard、权重复用审计、GPU 清理及注册释放通过。

**验收只覆盖本轮预热后的 Prefill 性能实验。** Decode 的原版 A/A 和候选 B/B 均出现输出变化，尚未定位原因；Decode 指标仅诊断，不作为有效提速或退化结论。r1 后续 Decode 失败、r2 预热输出差异和原始记录均保留，未补写成功状态。

## 文件

- `pp_ready_send.py`：发送就绪候选及私有同进程策略切换。
- `benchmark.py`：先保存观测，再区分原版重复、候选重复与跨策略输出一致性。
- `prepare_fairness.py`：生成冻结的 r3；后续重跑使用新的 run 目录，不修改原运行。
- `analyze.py`：CPU 重算请求指标、归属 GPU 分项，不启动 GPU。
- `build_report.py`：生成简短报告与总索引 Q02，保留失败和未知状态。
