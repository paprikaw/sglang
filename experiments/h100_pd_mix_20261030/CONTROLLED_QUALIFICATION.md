# 后续资格与归因对照

仅适用于 config 中 controlled_qualification / phase_isolation 为 true 的新运行；首轮冻结文件及结果不修改。

首轮用真实自由到达做 policy0 / policy1 的整条输出比较，部分输出不同。两次执行的实际批次会随调度改变，因而这不能单独诊断数值错误。后续改用相同初始请求分组：每个 PP2 同时接收8请求，固定初次入队顺序，每微批4请求；输入8192/256、输出8/64，仍包含分块 Prefill、批次收缩和可变消息。要求原生和提前发送逐请求完整 token 输出相同，且原生实际分组回执匹配；失败继续退回原生。

后续正式流量撤销固定分组，仍按原到达时间重放，使用 native typed messages 与 policy1 提前发送，记录实际提前发送次数。没有启用固定消息 lookahead policy9。

若 mixed pool 显示优势，还需排除仅靠 P/D 分工即可解释的收益：2×EP2 分成两个两卡阶段偏好池，4×单卡分成两个各两卡的池；池内按未完成请求数路由。2×PP2 同样比较按负载分配与 P/D 分池。整请求始终粘在原实例，不迁移阶段状态。

只针对首轮有信息量的流量补充这些对照，历史 Decode 网格、CPU恢复和首轮无变化基线继续复用。
