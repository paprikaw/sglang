## 2 Attention 效率应接近，Expert 效率随部署改变

This slide illustrates local kernel efficiency rather than only model-level Attention FLOPs. Use the saved B8 Decode protocol: Attention TP1, EP Attention DP2, PP two slots with max microbatch4. The saved profiles explicitly verify actual_local_batch4 in both layouts. EP GPU0/1 execute an unsharded Attention operator for the same layer on different request groups. PP GPU0/1 execute unsharded Attention operators in their respective stages on different microbatches. At matched token/context sizes and the same Attention implementation, these local operator shapes are comparable, so mean time per Attention layer-call should be close. Equal total batch alone does not establish this for arbitrary PP microbatching; this explicit two-slot example supplies the matched local batch. This is not an equality claim for complete per-rank Attention totals or call counts. Expert placement changes: each EP GPU holds E/2 experts for a layer; each PP GPU holds E experts for each of its local layers. EP exchanges routed tokens from B8 before expert execution; PP experts see the current local B4 microbatch. Averaged over experts at the same routing fanout, this gives approximately twice the tokens per EP expert. PP can thus have a larger local expert weight set and smaller per-expert GEMMs, reducing reuse and execution efficiency, while avoiding per-layer cross-GPU dispatch/combine. Tiles are conceptual E/2 versus E, not physical expert counts or measured durations. The drawing illustrates the deployment intuition; measured results follow on slides3-5. Pipeline communication and scheduling remain part of E2E and slide1. No new GPU timing.
