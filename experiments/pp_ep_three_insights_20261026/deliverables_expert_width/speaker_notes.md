Vertical layout revision. Both panels progress from top to bottom through a conceptual two-layer model. EP places the Attention and E/2 expert shard of each layer on each GPU. GPU columns within the left panel denote parallel rank placement, never a stage-to-stage progression. Each EP layer reads Attention -> Dispatch -> local experts -> Combine, then the next layer. PP stage1/GPU0 is above stage2/GPU1; each contains Attention -> E local experts. The downward orange arrow between stages denotes activation transfer. All operator and stage progression arrows point down. Expert block width represents expert-set size: a PP E-expert block is twice the width of an EP E/2-expert block. Attention blocks remain equal width. Boxes and arrows show logical order, not measured time or pipeline slot lengths. The saved protocol confirms Attention TP1, EP Attention DP2, global batch8, two PP B4 slots and actual Attention local batch4 in both layouts. PP passes each B4 microbatch through both stages, while EP splits requests across Attention ranks. Attention blocks use equal dimensions and matched local B4 labels to express comparable local operator shapes and expected average time per layer-call at matched token/context sizes. Equal total batch alone would not ensure matched local shapes for arbitrary PP microbatching. Each local PP layer has E experts versus E/2 in EP; PP sees current-microbatch routed tokens, while EP dispatch pools tokens from both ranks. PP can have larger expert working sets and fewer tokens per expert, reducing reuse. Measured data remain on the following three slides; no new GPU timing or exact Attention latency equality claimed.
