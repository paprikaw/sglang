# H100 Decode：Attention、Expert 与通信的绝对耗时

模型为完整 Qwen3.5-122B-A10B-FP8；数据来自已通过的 H100 r7 独立诊断 trace，**没有新跑 GPU 实验**。每个实际 rank 的 Decode CUDA Graph 次数见逐卡 CSV，按原分析的 `cudaGraphLaunch` correlation 对齐，排除首 token 的 Extend。

## 单位及能拆到的范围

- 单位为 **毫秒／每卡／一次实际 Decode Graph**。EP2 展示两卡均值，每卡执行完整 48 层；PP2 分阶段展示，每卡执行 24 层。8 请求时每卡／每槽为 4 请求，16 请求时为 8 请求。各 rank 只有 1–2 次 Graph，是短诊断，不是正式三轮请求指标的分项均值。
- **Attention 核心**只包括 FA3 主内核、FA3 自身归并及准备、Gated Delta Rule 递归内核。不含输入输出投影、卷积、归一化、KV 写入等，不能当成完整 Attention 模块耗时。
- **路由专家 GEMM**只包括 DeepGEMM grouped GEMM；不含路由、量化、排列、激活、共享专家。通用投影和共享专家未可靠拆开，统一保留在未归属内核中，不猜分。
- Dispatch／Combine 是 DeepEP 内核；NCCL 单列。FA3 的 Combine 属于 Attention，没有错误计入 MoE Combine。内核名 `internode_ll` 不代表本轮跨节点：本轮是同节点 NV6 GPU 对。
- 分项为 **kernel 累计运行时长**，不同流可重叠，**不能相加作 TPOT，不能除以 Graph 跨度当独占占比**。Graph 跨度是第一至最后 GPU kernel 的墙钟区间，另列展示。

## PP 边界传输与 Prefill 的缺口

PP 各阶段 Expert EP1，因此模型 Graph 内没有跨卡专家 Dispatch／Combine。**表中 0 仅表示没有这类 Graph 内内核，不表示 PP 总通信为零。** 阶段激活、元数据和反馈传输在 Graph 外；trace 有 NCCL send/recv，但驻留包含等上游数据的时间，当前没有纯链路传输与依赖等待的完整分离，不能把整段驻留冒充纯通信延迟。

正式 Prefill 测量没有独立同口径分项 trace。该诊断 trace 的初始 Extend 只有每条新增 1 token，**不能替代无旧缓存新增 4096 或长缓存新增 512 的正式 Prefill**。因此本报告不伪造这两种 Prefill 的 Attention／Expert／通信数字。

## 可以得到的观察

中等负载下，EP2 完整 48 层的路由 GEMM 两卡均值约 2.37 毫秒，PP 每阶段只有 24 层却仍需约 1.84–2.09 毫秒；PP 集中更多专家后的每层 GEMM 代价较高。EP2 DeepEP Dispatch＋Combine 的 kernel 累计均值约 1.91 毫秒，PP 模型层内避免了这部分。这些观测支持通信与专家计算的权衡，**尚不能精确归因正式 TPOT 的全部差额**。
